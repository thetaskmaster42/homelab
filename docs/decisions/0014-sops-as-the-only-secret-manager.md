# 0014 — SOPS+age is the only secret manager

**Status:** accepted, 2026-08-31
**Supersedes:** [ADR 0004](0004-two-tier-secrets.md), which specified two tiers.
**Supersedes:** ADR 0013 (automated OpenBao init), removed with it. Both, and the
whole OpenBao implementation, are preserved on the `feature-openboa` branch.

## Context

ADR 0004 split secrets in two: SOPS+age for what must live in git, OpenBao for
what applications read at runtime. The rule was clean — *"if ArgoCD needs it to
bring the platform up, it is SOPS. If an application needs it while running, it
is OpenBao."*

OpenBao was deployed, and then the second half of that rule never happened.

**Not one application ever read a secret from it.** Every credential in this
cluster arrives another way, and each of those ways is fine:

| Secret | Where it comes from |
|---|---|
| Grafana admin | SOPS bootstrap bundle |
| Tailscale OAuth client | SOPS bootstrap bundle |
| rh-dashboard basic auth | SOPS bootstrap bundle |
| PostgreSQL credentials | **generated by CloudNativePG**, never written down |
| drawio, excalidraw | no secrets at all |

That last row is worth pausing on. CloudNativePG already solves the hardest case
— a database password nobody chose, that exists only in a Secret the operator
made — and it does it without either tier.

Meanwhile OpenBao cost: an infra service, a raft volume on local disk, an unseal
step after every rebuild, and eventually a CLI subcommand plus 200 lines of
Python to automate that step away.

## The thing that settled it

Automating the unseal meant storing the unseal keys somewhere the CLI could read
unattended, which meant SOPS. ADR 0013 said so plainly:

> The age key becomes the single root of trust. OpenBao's unseal keys now live in
> the same repository, protected by the same key, as the SOPS bootstrap secrets.
> Its protection *at rest* is therefore equal to SOPS's, not better than it.

So the second tier ended up protected by the first. What remained was the runtime
half — dynamic credentials, rotation without redeploy, per-app policies, an audit
log — all real, and none of it in use by anything.

**A component that is not used, but must be kept alive, is not free.** It seals
on every restart, it holds a volume that `homelab nuke` destroys, and it is one
more thing to be wrong at three in the morning.

## Decision

SOPS+age is the secret manager. There is no second tier.

- Secrets that must exist before ArgoCD works go in
  `clusters/<name>/bootstrap-secrets.enc.yaml`, encrypted with age, applied by
  `homelab bootstrap`.
- Secrets an operator generates go in the same bundle.
- Credentials an operator can generate for itself — CloudNativePG's, and
  anything else that does the same — stay with that operator and are never
  written down at all. **This is the preferred shape**, and the first thing to
  reach for before adding anything to the bundle.

Charts consume them with `existingSecret` (the `grafana-admin` pattern), never by
having the chart generate its own — a chart-generated secret is regenerated on
every render, and under `automated` + `selfHeal` that is a pod restarting every
few minutes forever.

## What this gives up

**Dynamic, short-lived credentials.** A per-application PostgreSQL role that
expires in an hour is genuinely better than a static password, and nothing here
does that now. If an application ever needs it, that is the moment to bring
OpenBao back — the branch has a working, automated implementation.

**Rotation without a deploy.** Changing a secret now means editing the encrypted
bundle, committing, and re-running bootstrap. For a handful of static
credentials that is a reasonable amount of ceremony.

**An audit trail of secret reads.** There is none. On a single-operator homelab
that is an acceptable gap; on anything shared it would not be.

## Consequences

- **One mechanism to understand**, which for a cluster maintained by one person
  in occasional evenings is worth more than the capability given up.
- **Nothing unseals after a rebuild.** `nuke && install && bootstrap` needs no
  human step and has no component that starts in a broken state by design.
- **The age key is the single root of trust** — which was already true in
  practice after ADR 0013, and is now simply stated rather than arrived at by
  accident.
- **`homelab openbao` is gone**, along with `steps/openbao.py` and
  `scripts/openbao-configure.sh`.
- **The bar for bringing it back is a real consumer**, not a plan for one.
